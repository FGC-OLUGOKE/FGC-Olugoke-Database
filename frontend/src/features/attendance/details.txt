# Attendance Frontend - Backend Handoff

The attendance frontend currently uses localStorage through `attendance/api.js` so the UI works before the backend is connected. The backend developer should replace that storage implementation without changing the page/component contracts below.

## Pages and navigation

- `/attendance` records a new attendance session.
- `/attendance/sessions` lists saved and draft sessions. It owns edit, submit, and lock actions.
- `/attendance/history` is read-only. It filters and exports saved records.
- `/attendance/history/:sessionId` displays one session's details and exports that session.

The shared attendance navigation links these pages.

## Required backend operations

Replace the local functions in `frontend/src/features/attendance/api.js` with API requests:

- `GET /attendance/sessions/`
- `GET /attendance/sessions/{id}/`
- `POST /attendance/sessions/`
- `PATCH /attendance/sessions/{id}/`
- `POST /attendance/sessions/{id}/submit/`

The frontend currently expects these functions:

- `getAttendanceHistory()` -> array of sessions
- `getAttendanceSession(id)` -> one session or null
- `createAttendanceSession(payload)` -> created session
- `updateAttendanceSession(id, changes)` -> updated session
- `submitAttendanceSession(id)` -> submitted/locked session

## Session object

Each session should contain:

```json
{
  "id": "attendance-123",
  "type": "sunday-service",
  "checkpoint": "pre-sermon",
  "date": "2026-10-01",
  "eventName": "Sunday Service - Pre-Sermon",
  "status": "draft",
  "attendance": {
    "member-id-1": "present",
    "member-id-2": "absent"
  },
  "unregisteredAttendees": [
    { "id": "guest-1", "name": "Guest name", "status": "present" }
  ],
  "totals": {
    "total": 42,
    "present": 30,
    "absent": 12
  },
  "createdAt": "2026-10-01T09:00:00Z",
  "updatedAt": "2026-10-01T09:30:00Z",
  "submittedAt": null,
  "createdBy": "admin-id"
}
```

Allowed `type` values:

- `sunday-service`
- `bible-study`
- `prayer-meeting`

Allowed Sunday `checkpoint` values:

- `pre-sermon`
- `post-sermon`

Bible Study and Prayer Meeting should use `single` or `null` for checkpoint.

Allowed status values:

- `draft`: can be edited and submitted later
- `saved`: recorded but not locked
- `submitted`: final and locked
- `locked`: final and locked; treat the same as submitted

## Backend rules

The backend must enforce these rules even if the frontend already validates them:

1. Reject future attendance dates unless an explicit permission allows them.
2. Reject duplicate sessions for the same type, date, and checkpoint.
3. When updating an existing session, exclude that same session from duplicate detection.
4. Reject PATCH requests for `submitted` or `locked` sessions.
5. Submit must atomically mark the session as submitted/locked.
6. Preserve historical member attendance even if a member changes category or is deleted later.
7. Store unregistered attendees only on the attendance session; do not create permanent member records.
8. Scope visible members and sessions according to the authenticated user's role.

## Members

The existing member endpoint is currently used by the frontend:

- `GET /members/`

The response must include at least:

```json
{
  "id": "member-id",
  "firstName": "Amina",
  "lastName": "Okello",
  "category": "Adult"
}
```

The attendance frontend filters categories using: `Adult`, `Youth`, `Teenager`, and `Children`.

## History filters

The history UI sends filters locally today. A future API implementation may support query parameters:

- `type`
- `checkpoint`
- `month`
- `from`
- `to`
- `ordering`

Sunday checkpoint filtering must remain separate from church category filtering.

## Export

Excel, CSV, and print-to-PDF currently happen in the browser from the loaded session data. No backend export endpoint is required immediately. If server-side exports are later added, preserve the same columns:

- Date
- Attendance type
- Sunday checkpoint
- Status
- Total
- Present
- Absent
- Attendance rate

## Permissions

The backend remains the final authority. The frontend currently allows attendance access for Super Admin, Category Admin, and Pastorate roles. The backend must independently enforce:

- who can create or edit drafts/saved sessions
- who can submit and lock sessions
- who can view church-wide versus scoped attendance
- who can export attendance data
